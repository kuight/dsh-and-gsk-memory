# 决策记录（dsh 部署相关）

每条含：决策、日期、原因。原因即证据，无原因的条目不许入本文件。

## D-001 双版本共存：0.1.7 主力 / 0.1.5 跑 browser
- 日期：2026-09-27
- 原因：0.1.7-rc.2 下 dsh-browser 不兼容（上游 #102/#103，PR#103 为修复），
  而 browser profile（3081）是当前唯一可用的浏览器链路。若整体升级，浏览器能力直接失效。
  双版本可让主环境继续推进新特性，同时保住 browser 可用性。

## D-002 不手动打 PR#103，等官方合并
- 日期：2026-09-27
- 原因：手动打补丁 = 本地分叉源码，后续每次升级都要重新对齐，维护成本高且易漏；
  且 PR 未合并说明上游可能还会改接口，本地补丁会再次失效。
  等官方合并是成本最低、最稳的路径。

## D-003 approve-for-me 不强装
- 日期：2026-09-27
- 原因：审批类插件在 API 不兼容时的失效方式**不可预测**——它可能不是报错退出，
  而是静默放过本该拦截的操作，破坏"用户显式确认每次操作"的安全边界。
  对一个安全组件来说，"不确定它是否还在生效"比"确认它没装"更危险。
  相关硬规则见 tech-notes/hard-rules.md 第 2、3 条。

## D-004 试装隔离规则
- 日期：2026-09-27
- 原因：试装必须可回滚、可对比、零污染。具体三条：
  1. **快照对比**：试装前对主环境关键文件做字节数/时间戳快照，试装后逐项比对，
     确认零改动（见 handoffs/2026-09-27-dsh-017-trial.md 第 1 节）。
  2. **不复制 node_modules**：试装目录用独立 node_modules，避免依赖树互相污染。
  3. **记忆数据只用副本测试**：settings.yaml 等只拷副本到隔离 DSH_HOME 内测试，
     绝不改动主 `~/.dsh` 下的原件。
